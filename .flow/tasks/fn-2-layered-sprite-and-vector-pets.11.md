# fn-2-layered-sprite-and-vector-pets.11 Native .aseprite files and grid sprite sheets in packs

## Description
Let raster packs carry pixel art straight from Aseprite (the native `.aseprite` file) and plain grid sprite sheets, alongside task 3's explicit frames and Aseprite `json-array` exports (spec: API Contracts → Native Aseprite files, Grid sprite sheets; R20). All three forms produce the same in-memory layers, animations, parts and pivots, so everything after loading is unchanged.

**Size:** M
**Files:** `rust/crates/aipet-sprite/src/aseprite.rs`, `rust/crates/aipet-sprite/src/load.rs`, `rust/crates/aipet-sprite/Cargo.toml`, `rust/Cargo.toml`, `rust/crates/aipet-sprite/tests/**`, `avatars/samples/**` (new: a small native-Aseprite sample and a grid-sheet sample)
**Touches:** [rust/crates/aipet-sprite/**, rust/Cargo.toml, rust/Cargo.lock, avatars/samples/**]

### Approach
- Native files: try the `asefile` crate (MIT). Check that its `image` dependency unifies with the workspace's `image` 0.25 (iced pulls it in without codecs), so there's no second copy. If it doesn't unify, read the format directly: the documented chunk format is small for the subset needed (frames, cels, layers, tags, slices, RGBA and indexed modes).
- Map the native file like the export (task 3): tags `<layer>:<key>` become animations; tag direction and repeat map to loop modes; frame durations as given; slices named after parts give origins (R18), and per-frame slice keys give pose positions. Aseprite layers named after pack layers become those layers' art.
- Reject unsupported colour modes (greyscale is fine to convert; anything else is a reason line), linked or external tilesets, and anything over the size and frame limits. Check the limits on the header before decoding.
- Grid sheets: a frame index becomes a rectangle by `origin + (i % columns, i / columns) * (frame + gap)`; `ms` is a number or a list. Reuse task 3's frame type, so nothing downstream knows the difference.
- `--check-pack` reports native and grid packs like the others.

### Investigation targets
**Required:**
- `rust/crates/aipet-sprite/src/aseprite.rs` (task 3) — the export mapping to reuse
- `rust/crates/aipet-sprite/src/load.rs` (task 3) — limits, containment, all-or-nothing loading
- https://github.com/aseprite/aseprite/blob/main/docs/ase-file-specs.md — the native format

### Testing without Aseprite (it's paid)
- Fixtures are generated by the tests: a test-only writer for the documented subset (header, frames, layer, cel, tag, slice, palette chunks; RGBA and indexed) writes the `.aseprite` files. The matching `json-array` exports are written by hand. CI never runs Aseprite.
- Real-editor files: reuse the `asefile` crate's test `.aseprite` files if their licence allows (check it and record it in THIRD-PARTY-NOTICES), plus one file saved by LibreSprite (free, GPL; an older format version), as compatibility cases.
- Optional: one file made in a real Aseprite by the user, if they have it, checked in the hands-on task (8). Nothing depends on it.

## Key context
Aseprite stores `repeat` as a count in the file but as a string in the JSON export; normalise both into the same loop model.
